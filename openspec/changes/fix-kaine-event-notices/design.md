## Context

KaineMod 的高光提示来自 `l4d2_skill_detect` 翻译短语。直接触发警报车对应 `HandleCarAlarmTriggered_11`；该短语当前使用「高光操作」分类。按用户要求，此项只修改中文短语，不改插件源代码或触发条件。

机关尸潮额度与提示由 `l4d2_kaine_finite_hordes.sp` 处理。当前实现通过 `CDirector::OnMapInvokedPanicEvent` 的 detour 识别事件，并在尸潮生成回调中用 director mob timer 作为备用识别路径。玩家实测主动触发机关尸潮时提示会漏报，说明现有路径未覆盖部分实际地图触发方式或提示状态没有及时建立。修复应先识别漏报触发路径，再补足事件识别，避免只放宽计时器条件而把其他尸潮误纳入。

## Goals / Non-Goals

**Goals:**
- 将生还者直接触发警报车的简体中文提示改为「【铸币操作】kaine打响了警报车」对应格式，保留玩家名占位符与颜色标记。
- 让主动触发的 KaineMod 机关尸潮在事件开始时稳定显示现有额度提示。
- 保持额度计数和开始提示以同一机关事件状态为依据。
- 保持警报车、救援/最终关尸潮及 Boomer 尸潮排除在机关提示与额度逻辑之外。

**Non-Goals:**
- 不修改高光插件的源代码、通知触发条件或其他警报车提示类别。
- 不改变机关尸潮额度、计数策略、耗尽行为或其他玩法参数。
- 不调整非 KaineMod 模式的提示。

## Decisions

1. **直接警报车文案只改简体中文短语。**
   修改 `HandleCarAlarmTriggered_11` 的 `chi` 文本，将分类改为「铸币操作」，去掉玩家名后空格，并采用「打响了警报车」措辞。保留 `zho`、英文及其他由感染者控制导致触发的短语，避免把本需求扩展成全类通知重命名。

2. **先按实测触发路径修复机关事件识别。**
   检查 detour 参数和调用时机、地图脚本常见的机关触发方式、mob timer 状态以及插件加载与提示短语是否可用。用能稳定识别实际机关启动的事件信号建立/更新机关事件状态；仅在确认机关事件后发开始提示并应用额度。保持现有检测路径作为适用时的识别来源，避免由推测的单一原因决定实现。

3. **对同一事件只提示一次并保持来源隔离。**
   机关事件状态在首个有效信号时建立，后续回调不得重复发开始提示。警报车 panic type、救援流程及 Boomer 专用尸潮继续提前退出，不增加提示或计数。

4. **用实战回归场景验收。**
   在 KaineMod 中主动触发机关尸潮，确认开始额度提示可见且每个额度周期仅出现一次；另行触发警报车及救援/最终关尸潮，确认它们没有机关额度提示。通知分类通过翻译短语核对，不要求改源代码。

## Risks / Trade-offs

- **地图可能通过多种脚本路径启动机关尸潮。** → 结合实际漏报地图和日志验证识别来源；采用来源明确的事件信号，继续排除报警车和救援阶段。
- **放宽 timer 检测可能误识别其他尸潮。** → 不以 timer 活跃作为唯一的新判据；事件分类必须先确认机关来源。
- **短语的语言键或颜色标记修改不完整会导致显示异常。** → 只编辑指定 `chi` 项，并核对占位符 `%N` 与 SourceMod 颜色标签保留。

## Migration Plan

1. 更新指定的简体中文短语，并修复 Kaine 有限尸潮插件的机关事件识别/开始提示。
2. 编译并部署相关插件资源后，在 KaineMod 服务器上回归验证机关事件、警报车和救援尸潮提示边界。
3. 若出现误报或仍漏报，回滚有限尸潮插件改动；短语文本可单独回滚，不涉及配置迁移。

## Open Questions

- 哪一张地图、哪一个机关以及对应模式最容易复现漏报？实现时应优先用该场景确认实际触发路径；如暂时无法复现，需至少验证多种常见机关触发方式。
